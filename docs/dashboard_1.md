# Разработка административной панели «Торнус Склад»

## 1. Цель и контекст задачи

Административная панель — это веб-интерфейс, через который сотрудник склада или владелец малого бизнеса управляет данными: просматривает остатки, регистрирует движения товаров, анализирует статистику и импортирует данные из внешних файлов.

Перед началом разработки были сформулированы ключевые требования:
- интерфейс должен работать в браузере без установки дополнительного ПО;
- все данные берутся из FastAPI-бэкенда через HTTP-запросы;
- доступ к панели должен быть защищён паролем;
- страница аналитики должна содержать интерактивные графики.

Для реализации была выбрана библиотека **Streamlit** (Python). Это решение хорошо подходит для внутренних инструментов: не требует знания HTML/CSS/JS, позволяет быстро строить интерактивные интерфейсы на чистом Python и легко разворачивается в Docker.

---

## 2. Архитектура и структура

Панель состоит из нескольких ключевых компонентов:

```
dashboard/
  app.py              — точка входа: форма авторизации + главная страница
  api_client.py       — слой HTTP-запросов к FastAPI
  barcode_utils.py    — генерация PDF со штрих-кодами
  pages/
    1_Сводка.py       — ключевые метрики и предупреждения
    2_Товары.py       — CRUD справочника товаров
    3_Движения.py     — журнал и регистрация движений
    4_Аналитика.py    — графики и статистика
    5_Импорт.py       — загрузка товаров из CSV
    6_Штрих-коды.py   — генерация PDF со штрих-кодами
```

Streamlit автоматически строит навигацию по файлам в папке `pages/` — каждый файл становится отдельной вкладкой. Нумерация в именах файлов определяет порядок в меню.

### Слой взаимодействия с API (`api_client.py`)

Все HTTP-запросы к FastAPI инкапсулированы в одном модуле. Это позволяет страницам не знать об HTTP-деталях и работать только с Python-объектами:

```python
# Базовые HTTP-обёртки
def _get(path, params=None): ...
def _post(path, data): ...
def _put(path, data): ...
def _delete(path): ...
def _post_file(path, file_data, filename, params=None): ...  # для загрузки файлов

# Публичные функции для страниц
def get_products(category=None, low_stock_only=False): ...
def create_movement(data): ...
def import_products_csv(file_data, filename, on_duplicate): ...
```

Такое разделение упрощает отладку: если API изменит адрес или формат ответа, правки нужны только в `api_client.py`, а не во всех шести страницах.

## 3. Авторизация

Streamlit не имеет встроенной системы авторизации. Задача решалась через **session state** — хранилище переменных, привязанное к сессии браузера.

Механизм:
1. При первом открытии `app.py` проверяется `st.session_state["authenticated"]`.
2. Если флаг не установлен — показывается форма ввода пароля.
3. При совпадении с `DASHBOARD_PASSWORD` (переменная окружения) флаг устанавливается в `True` и страница перезагружается.
4. Каждая страница в папке `pages/` в самом начале проверяет этот флаг и останавливает выполнение при его отсутствии:

```python
if not st.session_state.get("authenticated"):
    st.warning("Необходима авторизация")
    st.stop()
```

Пароль передаётся через переменную окружения и не хранится в коде:
```python
DASHBOARD_PASSWORD = os.getenv("DASHBOARD_PASSWORD", "admin123")
```

## 4. Страница «Сводка» — ключевые метрики

Это главная рабочая страница для ежедневного использования. Она отображает:
- общее количество позиций на складе;
- количество позиций с нулевым остатком;
- общую стоимость склада в рублях;
- количество движений за сегодня и за месяц;
- таблицу товаров с низким остатком (ниже `min_stock`).

Метрики отображаются через `st.metric()` — компонент с поддержкой стрелок изменения значения. Товары с низким остатком выводятся в таблице через `st.dataframe()` с подсветкой строк.

---

## 5. Страница «Товары» — CRUD справочника

Реализованы три вкладки (`st.tabs`):

**Вкладка «Список»** — отображение всех товаров с фильтрами по категории и признаку низкого остатка. Данные получаются из API и конвертируются в `pandas.DataFrame` для удобного отображения.

**Вкладка «Добавить»** — форма с полями: наименование, артикул (SKU), категория, единица измерения, цена, минимальный остаток, описание. Используется `st.form()` для группировки полей и однократной отправки.

**Вкладка «Редактировать / Удалить»** — выпадающий список всех товаров, после выбора форма заполняется текущими значениями. Кнопки «Сохранить» и «Удалить» расположены рядом.

---

## 6. Страница «Движения» — журнал и регистрация

Поддерживаются четыре типа движений:
- **IN** — приход товара (увеличивает остаток);
- **OUT** — расход/отгрузка (уменьшает остаток, с проверкой достаточности);
- **TRANSFER** — перемещение между зонами (остаток не меняется);
- **INVENTORY** — инвентаризация (устанавливает точное значение остатка).

Журнал поддерживает фильтрацию по товару, типу движения и диапазону дат. При регистрации нового движения форма динамически адаптируется: для типа INVENTORY показывается подсказка «введите фактический остаток».

---

## 7. Страница «Аналитика» — графики

Используется библиотека **Plotly** для интерактивных графиков:
- **Столбчатый график** приходов и расходов за выбранный период (7 / 14 / 30 / 90 дней);
- **Таблица топ-товаров** по количеству расходных движений;
- **Круговая диаграмма** распределения остатков по категориям.

Данные для графиков получаются из отдельных аналитических эндпоинтов FastAPI, которые формируют агрегированные выборки на стороне базы данных.

## 8. Страница «Импорт» — загрузка из CSV

### Задача
Пользователь должен иметь возможность загрузить таблицу товаров из Excel/CSV и не вводить каждый товар вручную. В качестве примера использовался реальный файл поставщика с тремя колонками: название, единица измерения, количество.

### Реализация
Страница построена на двух вкладках:

**«Загрузить файл»:**
1. Компонент `st.file_uploader()` принимает CSV-файл.
2. Файл читается как `bytes`, декодируется в строку и парсится через `pandas.read_csv()`.
3. Показывается предпросмотр первых 10 строк.
4. Пользователь выбирает поведение при дублировании SKU: пропустить, обновить или ошибка.
5. Нажатие кнопки «Импортировать» отправляет файл на `POST /products/import/csv` через `_post_file()`.
6. Отображается статистика: создано / обновлено / пропущено / ошибки.

**«Скачать шаблон»:**
Генерируется пример CSV с правильными колонками и образцами данных. Пользователь скачивает его через `st.download_button()`, заполняет и загружает обратно.

После загрузки файла на той же странице появляется секция генерации штрих-кодов из загруженных данных — без необходимости переходить на другую страницу.

## 9. Страница «Штрих-коды» — генерация PDF

### Задача
Сотруднику склада нужны физические ценники со штрих-кодами для наклейки на товар. PDF-документ должен содержать штрих-коды в виде сетки (5 колонок × 6 строк = 30 штрих-кодов на страницу).

### Реализация — `barcode_utils.py`
Для генерации штрих-кодов использована библиотека **python-barcode**, для создания PDF — **ReportLab**.

Логика генерации:
1. Для каждого SKU генерируется штрих-код в формате **Code128** — универсальный формат, поддерживающий буквы, цифры и спецсимволы.
2. Штрих-код сохраняется в буфер как SVG, затем растеризуется в PNG через **Pillow** (PIL).
3. ReportLab размещает изображения в сетку на странице A4 с отступами.
4. Под каждым штрих-кодом печатается только **SKU** (без названия товара — для компактности).
5. Готовый PDF возвращается как `bytes` и предлагается для скачивания через `st.download_button()`.

Страница предоставляет два режима:
- **Все товары** — запрос всего справочника через API, генерация PDF.
- **Выбранные товары** — мультиселект с поиском по названию и SKU, генерация только для выбранных позиций.

## 10. Проблемы и их решения

### Проблема 1: Дублирующаяся навигация
**Ситуация:** Streamlit автоматически создаёт навигационное меню из файлов в папке `pages/`. При добавлении ручных `st.page_link()` в сайдбар каждой страницы возникло дублирование — два одинаковых меню.

**Решение:** Убраны все `st.page_link()` из блоков `with st.sidebar:` на всех страницах. Оставлена только кнопка «Выйти» в сайдбаре. Автоматическое меню Streamlit осталось единственной навигацией.

### Проблема 2: Серый квадрат вместо штрих-кода
**Ситуация:** При первой реализации вместо штрих-кода в PDF отображался серый квадрат-заглушка.

**Причина:** Библиотека `python-barcode` генерировала SVG, который ReportLab не умеет рендерить напрямую. Была попытка передать SVG напрямую в PDF — это и давало артефакт.

**Решение:** Добавлен промежуточный шаг растеризации: SVG → PNG через `cairosvg` или альтернативно через рендер в `io.BytesIO` с Pillow. Финальное изображение PNG встраивается в PDF через `reportlab.platypus.Image`.

### Проблема 3: Название товара на штрих-коде
**Ситуация:** Изначально под штрих-кодом печаталось полное название товара, что делало ценники нечитаемыми при длинных названиях.

**Решение:** Под штрих-кодом выводится только SKU — короткий и однозначный идентификатор, достаточный для сканирования и идентификации.

### Проблема 4: Состояние формы после импорта
**Ситуация:** После нажатия «Импортировать» и получения результата, при следующей перезагрузке страницы форма сбрасывалась и загруженный файл терялся.

**Причина:** Streamlit перезапускает весь скрипт при каждом взаимодействии пользователя — это фундаментальная особенность фреймворка.

**Решение:** Логика разделена: сначала файл читается и сохраняется в локальную переменную `content`, затем кнопки «Импортировать» и «Скачать штрих-коды» работают с уже прочитанным содержимым в рамках одного цикла выполнения скрипта.

## 11. Технологический стек

| Компонент | Библиотека | Назначение |
|-----------|-----------|-----------|

| Контейнер | Docker | Изоляция и деплой |

## 12. Итог

Административная панель реализует полный цикл работы со складом: от просмотра текущих остатков до генерации печатных ценников. Архитектура с выделенным `api_client.py` позволяет легко добавлять новые страницы без дублирования HTTP-логики. Все функции доступны через интуитивную навигацию Streamlit без необходимости знать адреса API или структуру базы данных.
